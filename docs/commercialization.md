# 봄날 상용화 정리: 수익 모델 · 서버 · 앱스토어 (2026-11-17)

지금 봄날은 **우리 둘만 쓰는 앱**으로 만들어져 있어요. 상용화의 첫 관문은 수익 모델보다 **"여러 커플이 각자 자기 데이터만 보게" 바꾸는 일**이에요. 아래는 지금 코드를 기준으로 무엇을 바꿔야 하는지, 돈은 어떻게 벌 수 있는지, 서버 비용·성능은 어떤지, 스토어에는 어떻게 내는지 순서로 정리했어요.

> 요금·정책 숫자는 2026-11 기준 검색 결과예요. 바뀌기 쉬우니 실제 결정 전에 공식 페이지에서 한 번 더 확인하세요. 비용 추정은 가정을 적어 둔 대략치예요.

---

## 1. 먼저 바꿔야 하는 것: 한 커플용 → 여러 커플용

지금 구조에서 상용화를 막는 부분:

| 지금 | 문제 | 바꿀 것 |
|---|---|---|
| 결혼식 정보가 DB 에 **한 줄**(`Wedding.id = 1`) | 두 번째 커플이 들어올 자리가 없음 | `Couple`(또는 Workspace) 테이블을 만들고 모든 데이터에 `coupleId` |
| 카테고리 이름이 **DB 전체에서 하나만**(`@unique`) | 다른 커플이 '스드메'를 못 만듦 | `(coupleId, name)` 으로 유일 |
| 이벤트·할 일·결제·사진·메모가 **모두 공용** | 다른 커플 데이터가 그대로 보임 | 서버 저장 함수 39개·화면 쿼리 전부에 `coupleId` 조건 |
| 잠금 = 카카오 승인 1팀 또는 비밀번호 하나 | 가입·초대 개념이 없음 | 회원가입 → 커플 만들기 → **배우자 초대 링크**로 합류 |
| 첫 카카오 로그인 = 관리자 (점검 문서 S3) | 상용에선 의미 없음 | 커플마다 만든 사람 = 관리자 |

이게 **가장 큰 작업**이에요 (거의 모든 파일을 건드림). 실수 한 번이 다른 커플 데이터 노출로 이어지니, 쿼리마다 조건을 붙이는 대신 "현재 커플" 을 한 곳에서 꺼내 쓰는 도우미를 만들고, 테스트로 "다른 커플 것은 안 보임"을 확인해야 해요. 여유가 되면 Postgres 의 행 단위 보안(RLS)을 2차 방어선으로.

같이 해야 하는 것: 계정·데이터 **삭제**와 **내보내기**(스토어 필수, 아래 4장), 점검 문서의 보안 항목(S1 차단 즉시 반영, S2 주소 검사, S4 잠금 기본값).

## 2. 수익 모델

### 이 서비스의 특징부터

- **사용 기간이 정해져 있어요.** 결혼 준비는 보통 6개월~1년이고, 식이 끝나면 대부분 안 써요. 오래 매달 내는 구독보다 **한 번 내는 이용권**이 자연스러워요.
- **둘이 같이 써요.** 한 명이 결제하면 커플 전체가 쓰는 게 맞아요 (결제 단위 = 커플).
- **돈이 오가는 시장이 커요.** 웨딩홀·스드메·예물·신혼여행은 금액이 크고, 업계 수익은 대부분 업체 연결(소개·박람회)에서 나와요.
- **무료 경쟁 앱·커뮤니티가 많아요.** 돈을 받으려면 "둘이 같이 쓰는 일정 + 결제·영수증 관리 + 메모" 처럼 무료 앱에 없는 확실한 이유가 필요해요.

### 후보 비교

| 모델 | 방식 | 장점 | 단점 | 추천 |
|---|---|---|---|---|
| **A. 무료 + 결혼 준비 이용권** | 기본 무료, 용량·고급 기능은 1회 결제 (예: 식 날짜 + 3개월까지) | 사용 기간과 맞음, 이해 쉬움 | 커플당 한 번뿐이라 매출 상한이 낮음 | ★ 1순위 |
| **B. 업체 제휴·연결** | 앱 안에서 웨딩홀·스드메·여행 견적 연결, 계약 시 수수료 | 매출 잠재력 가장 큼 | 영업 필요, 광고처럼 보이면 신뢰↓, 개인정보 제공 동의 필요 | ★ 사용자 모인 뒤 |
| **C. 웨딩플래너용(B2B)** | 플래너가 여러 커플 일정·결제를 관리, 월 구독 | 매달 들어오는 매출, 지금 '공유' 구조와 잘 맞음 | 플래너용 화면(여러 커플 한눈에) 따로 필요 | 2단계 실험 |
| D. 광고 | 배너·전면 광고 | 구현 쉬움 | 사용자 적으면 거의 0원, 감성 앱 분위기 해침 | 비추천 |
| E. 월 구독 | 월 2~5천 원 | 계산 단순 | 식 끝나면 해지, 가입 망설임 | 비추천 (A 로) |

### A 안 예시 (가정)

- **무료**: 일정·체크리스트·결제 기록 전부, 사진·첨부 합쳐 **300MB**, 메모 무제한
- **이용권 (예: 9,900~19,900원, 식 날짜 + 3개월)**: 저장 공간 5GB, 영수증 자동 정리(카테고리·금액 읽기), 엑셀·PDF 내보내기, 웨딩 예산 리포트, 축의금 관리 연동
- 용량 기준으로 나누면 **원가(저장 비용)와 가격이 같이 움직여서** 손해 볼 일이 적어요

**대략 계산 (가정)**: 활성 커플 1,000쌍 × 유료 전환 5% × 14,900원 ≈ **월이 아니라 총 75만 원**. 즉 A 하나로는 생활비가 안 돼요. A 로 서비스 비용을 메우고, 사용자가 수천 쌍 이상 모이면 B·C 로 키우는 그림이 현실적이에요.

### 결혼 후에도 쓰게 만들기 (선택)

식 끝나고 떠나는 걸 줄이는 방법: 축의금 정리 → 감사 인사 체크, 신혼 가계부, 기념일·결혼 1주년 리마인더. (축의금 관리 앱을 따로 만들고 있다면 이 자리에 붙일 수 있어요.)

### 결제 받는 방법

- **웹**: 토스페이먼츠 같은 PG 로 바로 결제 (수수료 낮음). 처음엔 **웹에서만 유료 판매**하는 게 가장 간단해요.
- **앱 안 디지털 상품**: 스토어 인앱결제가 원칙이에요 (애플 최대 30%, 소규모·구독은 15%). 한국은 외부 결제도 허용되지만 애플·구글 모두 외부 결제에도 **26%** 수수료를 받아 왔고, 2026-10 방송통신위원회가 이를 문제 삼아 과징금과 외부 결제 링크 허용을 명령했어요 (애플은 불복 검토 중). 상황이 바뀌는 중이라 앱 결제를 붙일 때 다시 확인하세요.
- 유료 판매 전 필요한 행정: **사업자등록**, **통신판매업 신고**, 이용약관·환불 규정.

## 3. 서버 성능과 비용

### 지금 구조

Vercel(도쿄 리전 서버리스 함수) + Neon Postgres + Vercel Blob(비공개 파일 저장). 화면은 열 때마다 서버에서 새로 그리고, 사진·첨부는 `/api/photos`, `/api/receipts` 함수를 거쳐서 내보내요.

### 얼마나 버틸까 (가정)

결혼 준비 앱은 **자주, 짧게** 쓰는 앱이 아니라 하루 몇 번 확인하는 앱이에요.

- 활성 커플 1,000쌍 = 2,000명, 1인당 하루 화면 20번 → **하루 4만 요청, 초당 평균 0.5개** 수준
- 이 정도는 서버리스가 아무 문제 없이 받아요. **병목은 계산이 아니라 DB 연결 수, 파일 전송, 저장 용량**이에요.

### 비용이 커지는 곳과 줄이는 법

| 항목 | 지금 | 상용에선 |
|---|---|---|
| **호스팅 요금제** | (확인 필요) Hobby 라면 | Vercel Hobby 는 **비상업적 개인 용도만** 허용. 돈을 받거나 사업 목적이면 **Pro (월 $20/개발자)** 가 필요 |
| **사진·첨부 저장** | Blob 이 없으면 DB 에 바이트로 저장, 큰 파일은 DB 에 조각을 이어 붙임 | DB 저장은 없애고 **Blob(또는 S3·R2) 필수**. 업로드는 브라우저 → 저장소 직접(서명된 업로드 주소)으로 바꿔 DB·함수를 안 거치게 |
| **사진·첨부 보기** | 매번 서버 함수가 Blob 에서 읽어 전달 | **짧게 유효한 서명 주소**로 저장소에서 바로 받게 (함수 실행·전송량 절약) |
| **저장 용량** | — | 커플당 약 100MB 가정(사진 200장 + 영수증) → 1,000쌍 ≈ 100GB. Vercel Blob 저장 단가는 GB당 약 $0.023 → **월 2~3달러 수준**으로 저장 자체는 싸요. 전송량·요청 수 요금을 같이 보세요 |
| **DB** | Neon, 한 커플 데이터는 많아야 수백 줄 | 커플 수가 늘어도 한 화면이 읽는 양은 그대로라 가벼움. `coupleId` 인덱스, **커넥션 풀러 주소** 사용, 무료 한도를 넘으면 유료 요금제(공식 가격 확인) |
| **리전** | 함수 도쿄(hnd1) | 사용자가 한국이면 함수와 DB 를 **같은 리전**에 (서울 리전 지원 여부는 각 서비스에서 확인) |

**대략 월 비용 (활성 1,000쌍 가정)**: Vercel Pro $20 + DB 유료 요금제(수십 달러 이하로 시작) + 저장·전송 수 달러 ≈ **월 5~10만 원대**. 1만 쌍이 되어도 구조만 위처럼 바꿔 두면 수십만 원대에서 크게 벗어나지 않을 거예요 (추정).

### 운영에 필요한 것

- **DB 구조 바꾸기**: 지금은 배포 때 `prisma db push` 로 맞추는데, 상용에선 되돌릴 수 있는 **마이그레이션 파일(`prisma migrate`)** 로
- **백업·복구**: Neon 의 시점 복구 기능 확인, 정기 백업
- **오류 알림**: Sentry 같은 에러 수집
- **요청 제한**: 로그인·업로드에 횟수 제한 (Vercel Firewall 등)
- **개인정보 국외 이전 고지**: Vercel·Neon 서버가 해외(일본·미국 등)라 개인정보처리방침에 국외 이전을 적고 동의를 받아야 해요

## 4. 구글 플레이 · 앱스토어

지금 봄날은 웹앱이고, 홈 화면에 추가하는 설정(manifest·아이콘)은 있지만 **서비스 워커가 없어서 오프라인·푸시가 안 돼요**.

### 방법 비교

| 방법 | 안드로이드 | 아이폰 | 작업량 |
|---|---|---|---|
| **PWA 만** (지금처럼 홈 화면에 추가) | ○ | △ (설치 안내가 불편) | 적음 |
| **TWA** (PWA 를 구글 플레이용 앱으로 감싸기, Bubblewrap·PWABuilder) | ○ 플레이 출시 가능 | ✕ | 적음 |
| **Capacitor** (웹 화면 + 네이티브 기능 감싸기) | ○ | ○ | 중간 |
| React Native 등 새로 만들기 | ○ | ○ | 큼 (비추천) |

**추천 순서**: ① 서비스 워커 붙여 PWA 다듬기 → ② **TWA 로 구글 플레이 먼저** → ③ 반응 보고 **Capacitor 로 iOS**.

### 구글 플레이

- 개발자 등록비 **$25 (1회)**
- **2023-11-13 이후 만든 개인 개발자 계정은 테스터 12명이 14일 연속 비공개 테스트**에 참여해야 정식 출시 신청이 돼요 (조직 계정은 예외, 2026년엔 실제 사용 여부도 본다는 말이 있음). 우리 둘 + 친구·가족 10명 정도로 베타를 겸하면 딱 맞아요
- 사업자로 **조직 계정**을 만들면 이 조건이 없지만 D-U-N-S 번호 등 서류가 필요
- 필요한 것: 개인정보처리방침 주소, 데이터 보안 양식, 앱 안에서 계정 삭제

### 앱스토어 (iOS)

- 개발자 등록비 **$99/년**, 빌드에 **Mac + Xcode** 필요 (없으면 클라우드 빌드 서비스)
- **4.2 최소 기능**: 웹사이트를 감싸기만 한 앱은 거절될 수 있어요. 푸시 알림(결제일·D-day), 카메라로 영수증 찍기, 공유 시트, 오프라인 보기 같은 **앱다운 기능**을 넣어야 해요
- **4.8 로그인**: 카카오 같은 외부 로그인을 쓰면 **Sign in with Apple** 같은 개인정보 보호형 로그인도 같이 제공해야 해요
- **5.1.1(v) 계정 삭제**: 가입이 있으면 앱 안에서 계정 삭제를 시작할 수 있어야 해요
- 유료 기능을 앱 안에서 팔면 인앱결제 규칙 (2장 '결제 받는 방법')

## 5. 단계별 계획 (제안)

| 단계 | 할 일 | 끝났다고 볼 기준 |
|---|---|---|
| **0. 지금** | 우리 둘이 쓰면서 불편한 점 모으기 | 결혼 준비 끝까지 실제로 써 봄 |
| **1. 여러 커플용** | 1장 전부, 보안 항목(S1~S4), 계정 삭제·내보내기, 파일 직접 업로드, Vercel Pro, 마이그레이션·백업·오류 알림, 개인정보처리방침·약관 | 다른 커플 데이터가 절대 안 보이는 테스트 통과 |
| **2. 무료 베타** | 서비스 워커(PWA), 결제일 알림, TWA 로 구글 플레이 비공개 테스트(12명·14일) → 출시, 지인·커뮤니티 20~50쌍 | 4주 뒤에도 쓰는 커플 비율(유지율), 가장 많이 쓰는 기능 확인 |
| **3. 유료화** | 사업자등록·통신판매업, 웹 결제로 이용권, 용량 한도 | 유료 전환율 측정 |
| **4. iOS·확장** | Capacitor + 푸시·카메라 + Apple 로그인, 업체 제휴·플래너용 실험 | — |

**한 줄 요약**: 지금 바로 돈 버는 장치를 붙이기보다, **1단계(여러 커플용 전환 + 보안)** 를 먼저 하고 **구글 플레이 무료 베타로 다른 커플이 실제로 계속 쓰는지** 확인하는 게 순서예요. 수익은 "이용권으로 비용을 메우고, 사용자가 모이면 업체 연결·플래너용으로 키우는" 구조가 이 서비스에 맞아요.
