# 봄날 E2E 테스트

Playwright 로 **사용자가 실제로 하는 흐름**을 고정한다. 구성·규칙은 `bx_store` 의 E2E 기획(`docs/plans/20261006-e2e-테스트-자동화-기획.md`, `docs/plans/20261007-ui-테스트-층-구분.md`)을 따르고, 봄날에 맞게 바꾼 점은 아래에 적는다.

## 1. 목표

1. 돈·데이터가 틀리거나 남에게 보이는 일을 막는다 — **커플 격리**, 결제·지출 합계, 첨부 파일
2. 여러 커플이 동시에 쓰는 상황을 재현한다 (테스트가 병렬로 서로 다른 커플을 만든다)
3. PR·main 푸시마다 자동으로 돈다 (`.github/workflows/test.yml`). 실패하면 리포트를 아티팩트로 남긴다

## 2. 구성

```
playwright.config.ts      프로젝트 3종, 테스트 서버, global-setup
e2e/
  env.ts                  테스트 DB·서버 주소, 위험한 DB 막기
  global-setup.ts         테스트 DB 를 지금 스키마로 (데이터는 지우지 않음)
  support/                단계 함수 — 테스트 아닌 것
    seed.ts               커플·사용자·이벤트·결제 만들기, 로그인(서명한 세션 쿠키)
    app.ts                화면 공통 (제목 기다리기, 탭)
    couple.ts             시작하기·초대·커플 나가기
    money.ts              결제·지출·예산·첨부
    events.ts             리스트·순서 바꾸기
    notes.ts              메모·그리기
  http/                   브라우저 없이 (폭 무관)
    access.spec.ts        로그인 이동, 로그인 없이 열리는 주소, 로그인 화면 보안
    isolation.spec.ts     다른 커플 데이터는 주소를 알아도 안 보임
  ui/                     desktop(1440)·mobile(430, 터치) 두 번 돈다
    onboarding / invite / payments / attachments / notes / reorder / support
```

| 프로젝트  | 대상        | 폭                          |
| --------- | ----------- | --------------------------- |
| `http`    | `e2e/http/` | —                           |
| `desktop` | `e2e/ui/`   | 1440 × 900                  |
| `mobile`  | `e2e/ui/`   | 430 × 900, isMobile·hasTouch |

## 3. bx_store 와 다른 점

| bx_store                          | 봄날                                                                                             | 이유                                                                 |
| --------------------------------- | ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------- |
| 개발 DB 를 그대로 씀 (개수·문구 고정 금지) | **전용 테스트 DB** 에 테스트마다 커플을 새로 만든다 → 개수·금액을 정확히 단언                    | 결제 합계(40만+40만=80만 같은 버그)는 정확한 숫자로만 잡힌다         |
| 인증 없음                         | 카카오 로그인 대신 **앱과 같은 키로 서명한 세션 쿠키**를 넣는다 (`seed.ts loginAs`)              | 카카오 화면은 테스트에서 못 띄운다. 쿠키 검증 코드는 그대로 탄다     |
| Bitbucket Pipelines               | GitHub Actions + Postgres 서비스                                                                  | 저장소가 GitHub                                                      |
| dev 서버                          | 로컬은 dev, **CI 는 빌드 결과(next start)**                                                       | 첫 요청 컴파일 대기가 없어 빠르고 운영과 같다                        |

테스트 DB 안전장치 (`e2e/env.ts`): DB 이름에 `e2e`/`test` 가 없거나 localhost 가 아니면 시작하지 않는다 (`E2E_ALLOW_REMOTE_DB=1` 로만 풀림). 테스트는 DB 를 지우지 않는다.

## 4. 작성 규칙 (bx_store 5절 그대로)

- **단계는 상태 없는 함수** (`support/*.ts`), 이름은 `goto`·`open`·`click`·`fill`·`choose`·`waitFor`·`expect` 로 시작
- **테스트 제목은 기대 동작을 문장으로** ("결제 예정 → 결제 완료로 바꾸면 예산의 예정에서 지출로 옮겨지고 합계는 한 번만")
- 흐름은 **여정 단위**로 (시작하기 → 초대 → 나가기)
- `networkidle`·고정 대기 금지. **화면 기준점**을 기다린다 — 화면 제목(h1, 스켈레톤이 끝난 신호), 에디터 도구 막대(에디터 준비), 입력 칸 포커스
- `force` 클릭·JS 클릭 금지
- 화면은 스트리밍이라 '찾을 수 없음'도 200 일 수 있다 → 격리는 **본문에 남의 내용이 없는지** + 주인이 열면 보이는지로 본다
- 넣기 전에 `--repeat-each=3` 으로 돌린다. 불안정하면 기준점을 고친다 (재시도 횟수로 덮지 않기)

## 5. 실행

```bash
# 로컬: Postgres 에 테스트 DB 하나 (처음 한 번)
createdb bomnal_e2e            # 또는 psql -c "CREATE DATABASE bomnal_e2e"

npm run e2e                                  # 전체 (dev 서버를 3200 에 띄움)
npm run e2e -- --project=mobile              # 프로젝트 하나
npm run e2e -- e2e/ui/payments.spec.ts       # 파일 하나
npm run e2e -- -g "커플 격리"                 # 이름으로 거르기
npm run e2e -- --headed --project=desktop    # 브라우저 보면서
npm run e2e:ui                               # 단계별 화면·DOM
npm run e2e:report                           # 마지막 리포트 (실패 스크린샷·트레이스)
E2E_DATABASE_URL=postgresql://…/bomnal_e2e npm run e2e   # 다른 테스트 DB
```

스키마를 크게 바꿔 테스트 DB 가 맞춰지지 않으면 테스트 DB 만 지우고 다시 만든다 (`dropdb bomnal_e2e && createdb bomnal_e2e`).
