## 1. 결제와 지출이 80만 원으로 보이는 문제

### 무슨 일인지

예산 탭에 같은 '플래너 계약금 40만 원'이 두 번 잡혀 있어요.

| 화면 칸 | 기록 종류 | 상태 |
|---|---|---|
| 결제 예정 | 결제(`Due`) — 이벤트 '스드메·본식 스냅 계약' 안 | '결제 완료' 안 누름, 11/8 · 8일 지남 |
| 최근 지출 | 지출 기록(`Expense`) — 같은 이벤트에 연결 | 실제로 쓴 돈 |

예산 계산(`src/app/budget/page.tsx:32-36`, `src/lib/budget.ts`)은

- 지출 = 결제 완료한 결제 + 모든 지출 기록
- 결제 예정 = 아직 안 낸 결제

로 더하고, **결제와 지출 기록을 이어 주는 칸이 없어서** 같은 돈인지 알 수 없어요. 그래서 스드메가 지출 40 + 결제 예정 40 = 80만 원이 되고 잔액이 40만 원 적게 나와요. 로컬에 같은 데이터를 넣어 '스드메 80만 원 / 300만 원, 잔액 220만 원'으로 똑같이 나오는 걸 확인했어요.

지금 '결제 완료'를 눌러도 안 고쳐져요. 이번엔 지출만 40 + 40 = 80만 원이 돼요.

### 당장 숫자 맞추기

둘 중 하나를 지우면 돼요. 영수증을 붙였다면 지출 기록을 남기고 결제를 지우세요 (이벤트 화면 → 그 결제 → 수정 → 삭제).

### 고치는 방향 (권장)

**결제 = 낼 날 일정, 지출 기록 = 실제로 쓴 돈** 으로 역할을 나누고 둘을 잇습니다.

1. `Expense` 에 `dueId`(선택, 결제 하나에 지출 하나) 추가
2. 결제의 '결제 완료'를 누르면 지출 기록 화면이 결제 내용(항목·금액·이벤트·카테고리·날짜)으로 채워져 열림 → 저장하면 그 결제가 완료되고 지출 기록과 연결. 영수증도 여기서 붙임
3. 지출 기록을 쓸 때 그 이벤트의 안 낸 결제가 있으면 "이 결제를 낸 건가요?"로 고를 수 있게
4. 예산 계산: **지출 = 지출 기록 합계만**, **결제 예정 = 안 낸 결제**. 결제 완료한 결제는 따로 더하지 않음
5. 이미 '결제 완료'된 결제(금액 있음)는 배포할 때 지출 기록으로 한 번 옮김 → 예산 탭 '지출'과 '지출 내역' 합계가 같아짐 (아래 M5도 같이 해결)
6. 지금처럼 같은 돈이 따로 있는 경우를 위해, 같은 이벤트에서 금액이 같은 안 낸 결제와 지출 기록이 있으면 "같은 돈인가요? 합치기" 안내

이렇게 하면 이벤트를 지워도 낸 돈이 예산에서 사라지지 않는 문제(M2)도 같이 풀려요 (지출 기록은 이벤트를 지워도 남음).

## 4. 문제없음을 확인한 것

- **날짜·시간대**: 모든 날짜를 그날 09:00 KST 로 저장, D-day·남은 날·달별 묶음이 서버 시간대와 상관없이 맞음 (자정 앞뒤 테스트 있음)
- **예산 나누기**: 반올림 뒤 합이 총예산과 정확히 같고, 불러와서 다시 저장해도 안 바뀜. 서버에서 다시 검사
- **카테고리 이름 바꾸기**: 이벤트·지출 기록 이름이 한 번에 같이 바뀜. '기타'는 못 지움
- **지출·증빙**: 증빙 한 장씩 올리고 10장 제한(서버도 확인), 실패하면 같은 지출로 다시 시도(중복 안 생김). 지출을 지우면 증빙 파일도 지움. 이벤트를 지워도 지출 기록은 남음
- **사진·증빙 파일**: 비공개 저장소, 앱 잠금을 거친 주소로만 보임
- **잠금**: 서버 저장 함수(서버 액션)까지 모두 문지기를 거침 — 로그인 안 한 사람·승인 대기·차단 상태로 저장 못 함(단 S1 의 쿠키 문제 제외). 로그인 쿠키 서명·만료·httpOnly·secure 정상. 관리자 작업은 DB 로 다시 확인
- **메모(브랜치)**: 서버에서 문서 구조 검사, 링크·코드 블록 없음, 그림 색·좌표 정리, 보기 화면은 HTML 을 직접 넣지 않아 스크립트 삽입 위험 없음. 글·체크리스트·그리기·지우개·되돌리기·저장·수정·다크 테마를 화면에서 직접 확인
- **캘린더**: 달 첫 요일·말일·해 넘김 계산 정상
